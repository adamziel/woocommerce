Fixture and Caveats

Dataset10000 HPOS orders, 5000 simple products, 800 variations on one variable productStackWordPress 7.0, WooCommerce 10.9.1, PHP 8.3.31, PHP-FPM max children 48.0
Fixture methodFixtures were generated through WooCommerce CRUD/application APIs: product objects, variation objects, wc_create_order, HPOS saves, order items, item meta, and analytics sync. Due scheduled lookup/import actions were drained before this rerun, and checkout stock was replenished through product APIs before measured checkout batches. No direct fixture INSERT/UPDATE writes were used.Stack pathnginx -> php-fpm with HTTP requests through nginx and PHP-FPM, not WP-CLI route execution.
MeasurementConcurrent curl fan-outs against one Docker site with SAVEQUERIES; reports include HTTP wall time, PHP wall time, query count, DB time, peak memory, slow SQL excerpts, batch wall time, summed request time, and effective parallelism.InterpretationGood for code-path shape and relative local pressure. Not a replacement for production RUM, k6 load curves, or multi-node database contention testing.
