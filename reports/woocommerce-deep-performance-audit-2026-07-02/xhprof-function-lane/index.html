Developer Handoff

PathTop function evidenceWhat to inspect
Core shipping/tax cart totals Core-only top self time: mysqli_query 57ms, wc_postcode_location_matcher 26.9ms, array_map 12.8ms over 20k calls, plus 42k is_numeric and 45k trim calls. Gateway stack nearly doubles queries and adds 4.5k callgraph edges. Tax and shipping range matching does real PHP work after broad SQL reads. For shipping, reduce the number of postcode rows fed into wc_postcode_location_matcher. For taxes, reduce broad range prequery and grouped rate query before PHP matching.
Checkout write path Core-only checkout self time is overwhelmingly mysqli_query: 2,351ms across 2,523 calls. Gateway stack adds about 61 queries and more bootstrap edges, but the bottleneck is still database writes. Repeated secondary costs include update_meta_cache, CSS parser calls from block/style work, DOMXPath::query, and 143k+ trim calls. Fix order/item/meta persistence and lookup refresh first. Gateway overhead is second-order on this path unless payment authorization adds external calls in a configured gateway flow.
Variable product page Core-only top self time: asort 1,003ms across 4,845 calls, mysqli_query 113ms, sanitize_title_with_dashes 70.6ms, WC_Data::get_prop 53.7ms, WC_Product_Variation_Data_Store_CPT::read_product_data 40.2ms. Gateway stack adds 40k calls each to WCPay\MultiCurrency\MultiCurrency::get_selected_currency and get_stored_currency_code. Core: inspect variation sorting/price formatting and repeated sanitization/property access. Gateway stack: WooPayments multicurrency hooks run once per variation/price touch and should cache selected/stored currency per request.
PayPal settings page Gateway-stack settings page spends 1,069ms self in curl_exec across 3 outbound HTTP calls, plus 264ms in mysqli_query. Inclusive path includes WP_Http::request, Requests curl transport, and Woo onboarding/task-list code. Identify and cache/defer remote calls made while rendering payment settings. This is not a SQL-only problem; a developer should trace HTTP calls from WooPayments/Jetpack provider onboarding and PayPal settings asset/reference-transaction checks.
Admin heavy order edit Core-only top inclusive path: Orders\PageController::output -> Edit::display -> Edit::render_meta_boxes -> do_meta_boxes -> WC_Meta_Box_Order_Items::output at 2,209ms inclusive. Core self time: mysqli_query 576ms across 3,095 calls, update_meta_cache 52.5ms, WC_Data_Store_WP::read_meta 30.7ms across 1,000 calls. Gateway stack adds 570ms in two outbound curl_exec calls. Core: keep pushing bulk order-item/meta priming and reduce per-item data-store reads in the order-items metabox. Gateway: prevent remote settings/onboarding calls from running on unrelated admin order edit pages.
